# 🔧 蒸馏模型性能排查操作手册

> **问题**: Scan2Cap baseline 76.9 → 蒸馏 58.1（下降 18.8 分）
> **目标**: 逐步定位性能下降的根因

---

## Step 1：检查 geometry_query 参数是否学到有意义的值

> 目的：确认蒸馏 loss 是否真的让 query tokens 学到了几何信息。
> 如果参数值和随机初始化差不多（mean ≈ 0, std ≈ 0.02），说明蒸馏 loss 没有生效。

### 在服务器上执行

```bash
cd ~/VG-LLM   # 你的项目根目录

python -c "
import torch
from transformers import AutoConfig
import sys
sys.path.insert(0, 'src')
from qwen_vl.model.modeling_qwen2_5_vl import Qwen2_5_VLForConditionalGenerationWithVGGT

CKPT = './checkpoints/ablation_geometry_query'

config = AutoConfig.from_pretrained(CKPT)
print('=== Config flags ===')
for k in ['use_distillation', 'query_type', 'query_size', 'geometry_dim']:
    print(f'  {k}: {getattr(config, k, \"NOT SET\")}')

model = Qwen2_5_VLForConditionalGenerationWithVGGT.from_pretrained(
    CKPT, config=config, torch_dtype=torch.bfloat16, device_map='cpu'
)

print()
print('=== geometry_query 参数统计 ===')
gq = model.geometry_query.data.float()
print(f'  shape: {gq.shape}')
print(f'  mean:  {gq.mean():.6f}')
print(f'  std:   {gq.std():.6f}')
print(f'  norm:  {gq.norm():.6f}')
print(f'  min:   {gq.min():.6f}')
print(f'  max:   {gq.max():.6f}')

# 初始化时: nn.init.normal_(self.geometry_query, mean=0.0, std=0.02)
# 如果训练后 std 仍然 ≈ 0.02 且 mean ≈ 0 → 没学到东西
if abs(gq.std().item() - 0.02) < 0.005:
    print('  ⚠️  std 非常接近初始化值 0.02，geometry_query 可能没有被有效训练')
else:
    print('  ✅ std 和初始化值差异明显，geometry_query 被训练过了')

print()
print('=== proj_geometry 权重统计 ===')
for i, layer in enumerate(model.proj_geometry):
    if hasattr(layer, 'weight'):
        w = layer.weight.data.float()
        print(f'  proj_geometry[{i}] weight: mean={w.mean():.6f}, std={w.std():.6f}')
"
```

### 怎么看结果

| 情况 | 含义 | 下一步 |
|------|------|--------|
| `std ≈ 0.02, mean ≈ 0` | ❌ geometry_query 没学到东西 | → 蒸馏 loss 没有生效，去 Step 3 |
| `std >> 0.02 或 mean 明显偏离 0` | ✅ geometry_query 被训练过 | → query 学到了东西但可能是错的，去 Step 2 |

## Step 2：对照实验 — 关闭 query injection 评测

> 目的：确认性能下降是 query tokens 注入导致的，还是训练过程本身破坏了 LLM。
> 
> 做法：用**同一个 checkpoint**，但推理时**不注入 query tokens**。

### 2.1 在服务器上修改代码

编辑 `src/qwen_vl/model/modeling_qwen2_5_vl.py`，找到约第 **2308** 行：

```python
        if (getattr(self.config, 'use_distillation', False)
                and getattr(self.config, 'query_type', None) is not None
                and _vis_mask_2d is not None
                and attention_mask is not None
                and position_ids is not None):
```

**改成：**

```python
        if False and (getattr(self.config, 'use_distillation', False)
                and getattr(self.config, 'query_type', None) is not None
                and _vis_mask_2d is not None
                and attention_mask is not None
                and position_ids is not None):
```

> 就是在 `if` 后面加 `False and `，让这个条件永远不成立。

### 2.2 跑评测

```bash
cd ~/VG-LLM

export LMMS_EVAL_LAUNCHER="accelerate"
export NCCL_NVLS_ENABLE=0

CKPT="./checkpoints/ablation_geometry_query"
OUTPUT="logs/eval_distillation_NO_INJECT"
mkdir -p $OUTPUT

accelerate launch --num_processes=4 --main_process_port 29501 -m lmms_eval \
    --model vgllm \
    --model_args "pretrained=$CKPT,use_flash_attention_2=true,max_num_frames=32,max_length=12800" \
    --tasks scan2cap \
    --batch_size 1 \
    --log_samples --log_samples_suffix no_inject \
    --output_path $OUTPUT
```

### 2.3 怎么看结果

| 结果 | 含义 | 结论 |
|------|------|------|
| 分数恢复到 ~76（接近 baseline） | Query tokens 是噪声 | 训练没有让 query 学到有用信息，LLM 主体没被破坏 |
| 分数仍然 ~58 | 训练过程破坏了 LLM 能力 | Query 的梯度回传干扰了 LLM 参数，需要调训练策略 |
| 分数介于两者之间（如 ~65-70） | 两方面都有影响 | LLM 受到部分损伤 + query 注入也引入了噪声 |

```python
                and getattr(self.config, 'query_type', None) is not None
                ...
```

## Step 3：检查训练日志确认蒸馏 loss 是否生效

> 目的：确认训练过程中蒸馏 loss 是否真的在计算。

### 3.1 查看训练日志

```bash
# 查看训练日志中 loss 的变化
tail -200 ./checkpoints/ablation_geometry_query/train.log | grep "loss"
```

如果训练日志中只打印了总 loss 而没有分别打印 distillation loss，你需要看 loss 的绝对值：
- **纯 LM loss 通常在 1.0-3.0 左右**
- **如果加上蒸馏 loss，总 loss 应该更高一些**（蒸馏 loss 通常在 0.5-2.0）

### 3.2 如果怀疑蒸馏 loss 从未生效

检查 `video_dict` 是否真的传到了 `forward()`：

在 `src/qwen_vl/model/modeling_qwen2_5_vl.py` 第 2376 行附近，临时加一行打印：

```python
        # ── 3DRS-style distillation loss (additive to LM loss) ────────────
        if (getattr(self.config, 'use_distillation', False)
                and video_dict is not None
                and _vis_mask_2d is not None):
            print(f"[DEBUG] distillation active! video_dict keys: {video_dict.keys()}")  # ← 加这行
```

然后跑一个 epoch 的一小部分：

```bash
# 用 --max_steps 100 只跑 100 步看看
torchrun --nproc_per_node=1 \
    src/qwen_vl/train/train_qwen.py \
    ...（你原来的参数）... \
    --max_steps 100 \
    --output_dir ./checkpoints/debug_distill_test
```

### 3.3 怎么看结果

| 输出 | 含义 |
|------|------|
| 看到大量 `[DEBUG] distillation active!` | ✅ 蒸馏 loss 正在计算 |
| 完全看不到 `[DEBUG]` | ❌ video_dict 没传进来 |
| 只有少量 `[DEBUG]`（很稀疏） | ⚠️ 只有部分样本触发了蒸馏 |

## Step 4：检查 except: pass 是否吞掉了异常

> 目的：确认蒸馏 loss 计算过程中是否有静默异常。

### 在服务器上修改代码

编辑 `src/qwen_vl/model/modeling_qwen2_5_vl.py`，找到 `compute_3d_distillation_loss` 方法中的两处 `except Exception: pass`（约 L1789 和 L1810）：

**修改前：**
```python
            except Exception:
                pass
```

**修改后：**
```python
            except Exception as e:
                import logging
                logging.warning(f"[DISTILL] geometry loss failed: {e}")
```

同样修改 depth 部分（如果有的话）。

然后跑 100 步训练看有没有 warning 输出。

## Step 5：根据排查结果决定下一步

### 场景 A：Step 1 显示参数没学到 + Step 3 确认蒸馏 loss 没生效

**原因**: feature 加载/shape 问题导致蒸馏 loss 被 `except: pass` 吞掉了。

**修复**:
1. 去掉 `except Exception: pass`，让异常 crash
2. 修复底层的 feature 加载/shape 问题
3. 重新训练

### 场景 B：Step 1 显示参数确实学到了 + Step 2 关闭注入后分数恢复

**原因**: Query tokens 学到了东西，但在推理时充当了噪声，破坏了 vision-language 对齐。

**可能的修复方向**:
1. 减小 `query_size`（从 16 减到 4 或 8）
2. 将 query tokens 放到 `<vision_end>` 之后（而不是视觉 tokens 和 `<vision_end>` 之间）
3. 增加 LM loss 的权重 / 降低蒸馏 loss 的权重
4. 冻结 LLM 主体参数，只训练 query + projection

### 场景 C：Step 2 关闭注入后分数仍然低

**原因**: 训练过程本身破坏了 LLM 能力。

**可能的修复方向**:
1. 降低学习率（当前 1e-5 → 试试 5e-6）
2. 冻结 LLM 主体，只训练 query tokens + projection heads
3. 检查是否因为 query injection 改变了序列长度，导致 LM loss 的梯度分布被改变

## 快速执行清单 ✅

按优先级排序，**先做最快能出结论的**：

```
□ Step 1: 检查 geometry_query 参数值（1 分钟）
□ Step 2: 关闭注入跑 Scan2Cap（~30 分钟）
□ Step 3: 查训练日志里的 loss 值（1 分钟）

```

> [!TIP]
