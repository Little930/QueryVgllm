## 2. 已发现并修复的 Bug

### Bug #1: eval 代码不识别蒸馏模型 ✅ 已修复

**位置**: [vgllm.py:83](file:///d:/桌面/QueryVgllm/src/lmms_eval/models/vgllm.py#L83)

**问题**: 原代码只检查 `use_geometry_encoder` 和 `use_vggt_feature` 来决定是否加载自定义模型类，蒸馏模型（`use_distillation=True`, `use_geometry_encoder=False`）会被当成普通 Qwen2.5-VL 加载，`geometry_query`（16×2048）等参数全部丢失。

```diff
- if getattr(config, "use_geometry_encoder", False) or getattr(config, "use_vggt_feature", False):
+ if getattr(config, "use_geometry_encoder", False) or getattr(config, "use_vggt_feature", False) or getattr(config, "use_distillation", False):
```

### Bug #2: generate 时 cache_position / attention_mask / rope_deltas 不兼容 ✅ 已修复

**位置**: [modeling_qwen2_5_vl.py forward()](file:///d:/桌面/QueryVgllm/src/qwen_vl/model/modeling_qwen2_5_vl.py#L2307)

**问题**: `_inject_query_tokens()` 在 prefill 阶段将序列从 T 扩展到 T+Nq，但 HF generate 不知道这件事，导致：
1. `cache_position` 长度 T ≠ `inputs_embeds` 长度 T+Nq → crash 或错误 mask
2. Decode step 的 `cache_position` 偏移 Nq → 错误的 KV cache 索引
3. `rope_deltas` 未调整 → decode step 的 position_ids 不连续

**修复方案**（在 forward() 中 `_inject_query_tokens` 之后）：
1. **Prefill 阶段**：扩展 `cache_position` 到 T+Nq，调整 `self.rope_deltas -= Nq`
2. **Decode 阶段**：在 `prepare_inputs_for_generation()` 中偏移 `cache_position += self._distill_query_offset`，并 pad `attention_mask`
3. 每次 prefill 开始时重置 `self._distill_query_offset = 0`，防止跨 generate 调用的值泄漏

### Bug #3: `_distill_query_offset` 跨样本泄漏 ✅ 已修复

**问题**: 如果样本 A 有视觉 token（offset=Nq），样本 B 是纯文本（无注入），decode step 会错误使用样本 A 的 stale offset。

**修复**: 在每次 prefill（`cache_position is not None and cache_position[0] == 0`）时重置 `self._distill_query_offset = 0`。

## 3. 推理安全性分析

### 完整审查路径

```
eval 命令 → vgllm.py (VGLLM.__init__) → AutoConfig → model class 选择
    → generate_until() → processor → model.generate()
        → prepare_inputs_for_generation() → forward()
            → embed_tokens → visual → _inject_query_tokens → self.model() → lm_head
```

### 各环节安全性

| 环节 | 状态 | 说明 |
|------|------|------|
| 模型类加载 | ✅ | 已修复 vgllm.py 第 83 行 |
| Query injection + KV cache | ✅ | cache_position / attention_mask / rope_deltas 已对齐 |
| 蒸馏 loss 推理行为 | ✅ | `labels=None` + `video_dict=None` 时不计算蒸馏 loss |
| Output 裁剪 | ✅ | HF generate 返回原始 input_ids + 新 token（不受 embedding 层注入影响） |
| Position IDs 传播 | ✅ | Query tokens 共享视觉段的 max position，不破坏位置连续性 |
| Processor/Tokenizer | ✅ | eval 脚本自动从 base model 复制补全 |

### 训练路径安全性

| 场景 | 影响 |
|------|------|
| 训练（`cache_position=None`） | ✅ 无影响 — 所有新逻辑被 `cache_position is not None` 守卫 |
| 非蒸馏模型 | ✅ 无影响 — `_nq_injected=0`, `_distill_query_offset=0` |
| 推理 batch_size=1 | ✅ 修复生效 |
| 推理 batch_size>1 | ⚠️ `_inject_query_tokens` 的 `torch.stack` 仍要求同长度（预先存在的限制） |

### 4.2 评测命令

#### Scan2Cap（场景描述生成）

```bash
cd ~/VG-LLM
export LMMS_EVAL_LAUNCHER="accelerate"
export NCCL_NVLS_ENABLE=0

CKPT="./checkpoints/ablation_geometry_query"
OUTPUT="logs/eval_distillation_geometry_query"
mkdir -p $OUTPUT

accelerate launch --num_processes=4 --main_process_port 29501 -m lmms_eval \
    --model vgllm \
    --model_args "pretrained=$CKPT,use_flash_attention_2=true,max_num_frames=32,max_length=12800" \
    --tasks scan2cap \
    --batch_size 1 \
    --log_samples --log_samples_suffix distill_geometry \
    --output_path $OUTPUT
```
